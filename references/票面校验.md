# V18 伴随审计格式

日夹总验收用 `python3 scripts/check_day.py <日夹>`；缺失的审计或赛前快照会标为“未验证”并返回非零。本地文件和哈希只证明内部一致性，不证明网页事实、真实采集时间或实际票面；历史稿默认不回溯新口径。

```bash
python3 scripts/audit_delivery.py evidence <日夹>/01-竞彩分析.md <日夹>/evidence.json
python3 scripts/audit_delivery.py ticket <日夹>/01-竞彩分析.md <日夹>/tickets.json
python3 scripts/audit_delivery.py freeze <日夹>/01-竞彩分析.md <日夹>/predictions.json --output <日夹>/predictions-frozen.json
```

## 证据清单（evidence.json）

每个候选三位编号下列出 `analysisJs`、`detail`、`list_spf`、`coach`、`referee`、`cat` 六个证据文件；每项是 `{"path":"_raw/…","sha256":"64位小写十六进制"}`。审计核对候选集合、01a 过程标记、原文非空、路径位于本日夹 `_raw/` 且哈希一致。无候选写 `{"matches":{}}`。文件存在和哈希一致不等于来源、对阵、伤停或发布时间已核。

## 票面清单（tickets.json）

空仓写 `{"tickets":[]}`。每张实际票包含 `name`（稳或博）、`stake_yuan`、`multiple`（正整数）、`odds_captured_at`（带时区）、`joint_probability`（`独立近似`或`保守调整`）、`rho` 和 `legs`。每腿包含三位 `match_id`、`play`、`choices`；每个购买选项必须列 `option`、十进制 `sp`、`p_model`、`p_conservative`。一腿多档必须列全，不能只填高概率或高赔率档。

`p_conservative` 由 `scripts/conservative_probability.py` 的 λ 区间角点法导出，不得手填；lint 会重算比对。`rho` 是票级相关性折扣，`联合保守P = 各腿 p_conservative 乘积 × rho`；账本标定前一律写 `"未标定"`（审计按 1.0 处理，即不额外折扣），标定后写 0..1 的数值。`joint_probability` 为 `保守调整` 时 `rho` 必填。

```json
{"tickets":[{"name":"博","stake_yuan":"4","multiple":1,"joint_probability":"保守调整","rho":"未标定","odds_captured_at":"2026-11-05T10:00:00+08:00","legs":[{"match_id":"005","play":"进球数","choices":[{"option":"2球","sp":"2.80","p_model":"0.40","p_conservative":"0.37"},{"option":"3球","sp":"3.20","p_model":"0.36","p_conservative":"0.33"}]},{"match_id":"012","play":"胜平负","choices":[{"option":"主胜","sp":"1.60","p_model":"0.68","p_conservative":"0.64"}]}]}]}
```

本金 = 2 元 × 各腿档数乘积 × 倍数。每条完整路径的派彩 = 2 元 × 倍数 × 该路径 SP 乘积；路径概率 = 各选项概率乘积。整票期望返还 = 所有路径的“概率 × 派彩”之和，整票 EV = 期望返还 / 本金 − 1。保守返还按同一公式用 `p_conservative` 计算后再乘 `rho`，**保守 EV ≤ 0 拒绝出票**，不要求每条路径返还翻倍。

独立相乘只是近似，不是相关性证明。`保守调整`表示已按同联赛、同赛果驱动因素等相关性下调，下调幅度就是 `rho`；保守概率不得高于模型概率。同场多腿仍禁止冒充跨场独立串。审计还检查候选、观望禁票、本金、完整路径和赔率采集时间；实际开售、盘口结算规则、清单与真实票面一致仍须人工核对。01 非空仓须同时写 `账本=过`、`EV审计=过`，不能只写声明而不提供可计算清单。

## 赛前冻结与评估

`predictions.json` 含 `day`、带时区的 `captured_at`、`fixtures` 数组。每场需有 `match_id`、带时区的 `kickoff_at`、`lean`（主胜/平/客胜/不定）以及 `p_model`（主胜、平、客胜之和为 1，或 `null` 表示未估）。开赛前生成只写一次的 `predictions-frozen.json`，记录稿件和清单哈希；本地文件并非防篡改证明，须另行归档并核对可信时间。

赛后另录赛果、实际本金与派彩，写入 `pred-ledger.csv` 与 `tickets-ledger.csv`（列定义见 `复盘条款.md`），再跑 `python3 scripts/score_ledger.py <账本目录>`。概率完整的场计算 Log Loss、Brier 和校准；倾向不定不进单选命中率分母；收益以实际票面为准，不从命中率推算。小样本只报告计数与区间，不宣称稳定盈利能力。
