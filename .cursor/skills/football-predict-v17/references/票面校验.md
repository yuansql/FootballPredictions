# V17.4.99 伴随审计格式

`lint_draft.py` 只检查稿件规则；不得把 `翻倍=过` 当作计算证据。候选取证与票面审计分别运行：

```bash
python3 scripts/audit_delivery.py evidence <日夹>/01-竞彩分析.md <日夹>/evidence.json
python3 scripts/audit_delivery.py ticket <日夹>/01-竞彩分析.md <日夹>/tickets.json
python3 scripts/audit_delivery.py freeze <日夹>/01-竞彩分析.md <日夹>/predictions.json --output <日夹>/predictions-frozen.json
```

## 证据清单（evidence.json）

每个候选三位编号下列出 `analysisJs`、`detail`、`list_spf`、`coach`、`referee`、`cat` 六个证据文件；每项是 `{"path":"_raw/…","sha256":"64位小写十六进制"}`。审计核对候选集合、每份 01a 五个过程标记，以及每个原文文件非空、位于本日夹 `_raw/` 且哈希一致。无候选可写 `{"matches":{}}`。文件存在、哈希一致**不等于**网页来源、对阵、伤停或发布时间已核；人工查验仍必须做。

## 票面清单（tickets.json）

空仓：`{"tickets":[]}`。每张实际票以 `name`（稳或博）、`stake_yuan`、`multiple`（正整数）、`odds_captured_at`（带时区的赔率采集时间）、`legs` 描述；每腿有 `match_id`（三位字符串）、`play`（玩法）、`choices`（所有购买选项的 `option` 与十进制 `sp`）。一腿多档必须**列全**，例如进球区间 2/3 球就是两个 `choices`，不能只填低赔率档。

```json
{"tickets":[{"name":"博","stake_yuan":"4","multiple":1,"odds_captured_at":"2026-11-05T10:00:00+08:00","legs":[{"match_id":"005","play":"进球数","choices":[{"option":"2球","sp":"2.80"},{"option":"3球","sp":"3.20"}]},{"match_id":"012","play":"胜平负","choices":[{"option":"主胜","sp":"1.60"}]}]}]}
```

本金 = 2 元 × 各腿档数乘积 × 倍数。每条命中路的返还 = 2 元 × 倍数 × 该路径各腿 SP 乘积；**每条**必须 ≥ 该票本金的 2 倍。审计检查候选编号、观望禁票、跨场、本金和所有路径。它不核验实际开售、赔率时间、盘口一致性或结果。若缺少具体 SP、档数或本金，标“未验证”，不得宣布翻倍已机器核过；需要人工核对票面与清单一致。

## 赛前冻结与评估

`predictions.json` 含 `day`、带时区的 `captured_at`、`fixtures` 数组。每场需有 `match_id`、带时区的 `kickoff_at`、`lean`（主胜/平/客胜/不定）以及 `p_model`（主胜、平、客胜之和为 1，或 `null` 表示未估）。在开赛前生成只写一次的 `predictions-frozen.json`，记录稿件和清单哈希；**本地文件并非防篡改证明**，须另行归档并核对时间戳。赛后另录赛果、实际票面盈亏：倾向不定不入单选命中率分母；只有赛前概率完整的场才算概率校准；收益以实际下注与派彩为准，不从命中率推算。小样本只报告计数和区间，不宣称盈利能力。
