# 足球预测与出票执行器 · V18 概率校准版

**先回答比赛怎样踢，再回答某个选项是否值得买。** 方向、排除、倾向来自球队情报、对位和可复核的比赛过程；赔率不是球队情报，但可用于市场基准、校准对照和 EV 计算。lint 全绿只代表流程一致，不代表预测准确或长期盈利。

**只改源仓，改后运行 `bash scripts/sync-skill-bundle.sh`。** 冲突顺序：本文件 > `球赛预测框架.txt` > 联赛插件 > 人设。规则版本须在赛前冻结；历史赛果只能进入后续时间外验证，不能回写当场概率。

## 强制作业流

0. 文首先写 `交卷模式=研究板|下注单`。研究板主交付是概率与方向，下注单主交付是实际票面或空仓。
0b. 全表先粗筛，再写【票面候选】（通常≤4，研究板可无）。认真拆集合必须等于候选；票腿必须来自候选。候选按可研究性选择，不因未开售、赔率不漂亮或串关翻倍失败提前剔除。
1. 对候选完成【取证清单】并落盘。捷报用于编号、对阵、竞彩 SP、近况和基础技统；俱乐部/联赛官方、Transfermarkt/FotMob 等可补伤停与赛程；Understat 等同源 xG 数据可用于对应联赛。不得把任何商业站点当全能唯一事实源。
2. 写【情报叙事】【球队画像】【比赛剧本】。明确已知、未知和互相冲突的证据；没有优势侧就 `方向=观望｜倾向=不定`，不得硬装不败。
3. 在查看 EV 前写【方向冻结】：`冻排=·｜冻向=·｜冻侧=·｜已冻=是`。新伤停或新数据可修订，但必须写 `对照盘口修订=` 的具体原因；不能只因 EV 不好看改故事。
4. 建立 λ 点估计和保守区间；使用动态截断比分矩阵，同时计算胜平负、让球、总进球和精确比分。所有玩法共用同一矩阵，不得各用一套概率。
5. 采齐该场**全部在售玩法**的实际 SP（胜平负/让球/总进球/比分）并写采集时间；未开售写 `未开售`。缺 SP 不得宣布“无可买/无推荐”。
6. 写【玩法路由】：按结果清晰度、净胜清晰度、总 λ 稳定度选出该场值得研究的价格线，再用实际 SP 计算真实 EV。先看数据质量，再看保守 EV；任何市场都可观望，不要求从胜平负机械“降维”到另一个负 EV 市场。路由只决定研究哪条价格线，不改 λ、不改矩阵、不放宽出票闸。
7. 输出【结果预测】【研究推荐】【研究玩法】【出票】【全场汇总表】（多场）和【今日票面】。比分与总球缺乏可靠分布时可弃权，不再强制凑三格或进球区间。
8. 运行 lint、证据审计、非空仓票面审计和赛前冻结；按真实结果写 `证据审计=`、`票面算术=`、`赛前冻结=`，未运行写未验证。

python3 scripts/conservative_probability.py --lam-h 1.62 --lam-a 1.05 --h-interval 1.38,1.86 --a-interval 0.86,1.28 --handicap -1

## 一、分诊与候选

| 池 | 规则 |
|---|---|
| 粗筛 | 全表每场≤3行，写可验证线索、主要未知和进/剔 |
| 【票面候选】 | 认真拆对象，通常≤4；不是出票承诺 |
| 认真拆 | 只拆候选，写取证、过程、冻结、概率与风险 |
| 观察骨架 | 非候选≤6行；事后进票须先升候选并补齐过程 |
| 票面池 | 0～若干腿，腿⊆候选；可以全空 |

候选评级只描述证据与剧本可信度，不替代 EV：

| 级 | 含义 |
|---|---|
| ★★★★ | 核心槽完整、方向有独立证据、模型不确定度较低 |
| ★★★ | 可研究但存在明确弱点，保守概率须反映 |
| ★★ | 证据不足，只研究，不进票 |

每个候选写【市场漏】记录模型与市场差异；它是诊断信息，不是出票公式。真实出票使用实际 SP 的盈亏平衡概率和 EV，不能用 `我估-去水隐含` 代替。

## 二、取证、口径与伤停

### 多源与落盘

- 第三方荐单、AI 结论、专家连红和聊天室不得进入证据链。教练、裁判、捷报猫页面只摘可核事实，不采其推荐方向。
- 候选默认保存 analysisJs、detail、竞彩列表、教练、裁判和猫页；关键伤停/xG 若由其他源补齐，也保存原文并标 URL/时间。
- 【认真拆必采】写 `伤停=有源|未见|槽弱｜机会代理=…｜初盘=真开盘|竞彩现盘|缺`。`初盘=缺` 不伪造成开盘路径。
- 【主菜质量层】写机会质量、风格对位、赛程轮换、比赛状态；缺就写缺，不编 xG/PPDA。
- 【比赛性质】标联赛/杯赛/欧战/友谊与层级差；杯赛轮换未知只降低数据质量，不自动锁或排某侧。

### 情报档

```text
情报档=充足|偏薄|不足｜动作=PROCEED|CAUTION|STOP｜伤停=有源|未知｜一句=具体缺槽
弱置信=是|否
```

关键伤停、对阵身份或开赛时间未核，不能出票。数据不足仍可研究，但概率应给区间或标未估；不得用确定语气掩盖未知。

### 伤停按边际影响

- “已核”只认本场官方名单、赛前发布会、本场缺阵页或正式首发；上一场未首发只能标待证。
- 新缺/旧缺是输入，不是结论。评估球员角色、替补差距、对位、该影响是否已反映在近年比赛和当前市场中。
- 旧缺可以仍有边际影响；新缺也可能因同水平替补而很小。禁止固定“新缺才有效”或固定乘 λ 系数。
- 写【伤停排除】时必须说明 `核心缺=`、`打不了=` 和证据；写不出具体机制就只降置信，不排边。

### 概率与市场角色

| 数据 | 合法用途 | 禁止 |
|---|---|---|
| 球队/阵容/赛程/xG | λ、对位、情景和不确定度 | 无来源精确数 |
| 市场去水概率 | 市场基准、校准比较 | 当盈亏平衡概率 |
| 实际可买 SP | `p_be=1/SP`、`EV=p×SP-1` | 低赔直接等于稳 |
| 盘口/赔率变化 | 风险标记、新信息核对 | 单独决定排除或方向 |

## 三、剧本、方向与反证

排除和倾向须能由情报与对位解释，再与模型概率核对。禁止“赔率低所以稳”“客热所以不能买”“低结构所以选不败”。

```text
排除=主胜|平|客胜|暂缓｜理由=具体证据｜质疑=市场/数据风险|无
剩余={…}｜二次=倾斜主胜|倾斜平|倾斜客胜|分不清
方向=锁主|锁客|锁平|主不败|客不败|观望｜倾向=主胜|平|客胜|不定
```

- 排主胜/客胜前写【强弱对位】：被排方强项、对方弱项、能否打得到；主场描述须有数据而非口号。
- 允许集：锁主={主胜}，锁客={客胜}，锁平={平}，主不败={主胜,平}，客不败={客胜,平}，观望=∅。倾向必须属于允许集。
- 分不清且没有一侧就是观望，写弃因；不进入单选命中率和票面。不要为覆盖率先验排除某结果。
- 低结构、深让、豪门客场、双新军、跨市场差异和 V15.6 名称都只是【风险标记】，不得自动改 λ、方向、比分或出票。
- 【反剧本收据】写最强反方向、触发路径和为何仍保留主剧本；无法反驳时降低置信或观望，不强制选不败。
- 【杯赛揭幕闸】【低结构平优先闸】【深盘陷阱确认书】【欧战深盘客闸】【双新军锁主闸】保留为提示标签，不是概率补丁。

## 四、统一概率模型

详细公式见 `references/p_model手算.txt`。

1. 输入按同一来源、同一赛事、同一时间窗处理。xG 与 xGA 必须同源同口径；明确是否含点球。原始进球不能标成 npxG。
2. λ 应考虑联赛基准、主客拆分、对手强度、时间衰减与样本收缩。收缩强度由历史验证，不固定 0.65/0.60。
3. 输出 `λ_H=`、`λ_A=`、`λ校准=` 和 `λ区间=H[lo,hi]/A[lo,hi]`，并写 `区间依据=`（样本量、口径、阵容未知中哪个来源撑开了区间）。算不出就 `p_model=null`，不编造。
4. 独立泊松是当前可复核基线，不是足球真理。尾部截断到遗漏概率 <0.0001；高比分必须扩展，不固定 0～5。
5. 同一矩阵派生 P(主/平/客)、让球、总进球和比分。Dixon–Coles/负二项只在时间外验证优于基线后启用。
6. V15.6 的 StarFactor/Kryptonite/Jinx/Zombie/Edge_Refine 不再修改概率。旧 H2H、排名或赔率形态若有用，必须先进入可检验特征并验证。
7. 精确比分从矩阵排序并结合情景筛选；可以弃权。不得强制净胜≥3、强制大球、按整轮小胜比例改比分或凑固定三格。

【情景路径】与【比分推荐 · Top3】是解释层，不能盖过矩阵概率。`path weight`、`ε` 等人工数字若未经估计不得伪装成模型输出。

## 五、真实 EV 与出票

对每个实际可买选项：

```text
p_be = 1 / 实际SP
EV = p_model × 实际SP - 1
Edge_pp = p_model - p_be
p_market = 各项倒数归一化（仅市场基准）
```

- 例：SP=1.80，p=51.1%，即使高于去水市场概率，EV 仍约 -8.0%。
- 出票须核心数据足够、保守 EV>0、概率来源与玩法一致、SP 时间有效，并符合用户预算和开售限制。
- 点估计 EV>0 但保守 EV≤0 → 研究保留、出票观望。没有统一的 1%/3% 神奇阈值。
- **保守概率由 λ 区间机械导出，不手工下调**：在 λ_H/λ_A 区间的四个角点各跑一次同一矩阵，对每个选项取最差（最小）概率。运行 `python3 scripts/conservative_probability.py --lam-h · --lam-a · --h-interval lo,hi --a-interval lo,hi [--handicap -1]`，把输出的 `保守P=` 原样抄进稿件。
- 角点法让不同玩法自动获得不同折扣：总进球只依赖 λ 总量、对主客分配不敏感，让球对分配极敏感。手工统一打折无法区分二者，结果必然要么总进球过度保守（漏正 EV），要么让球保守不足（买进负 EV）。
- λ 区间因此直接决定能否出票，`区间依据=` 必须写实；不得为了过闸把区间收窄，也不得为了显得稳健把区间放宽。
- 多腿联合保守概率 = 独立乘积 × ρ。ρ 是相关性折扣，只能由 `tickets-ledger.csv` 标定；未标定时写 `ρ=未标定`，不得把猜测值伪装成估计结果。
- 胜平负不值得买时可独立评估让球/总进球，但不是必须顺序“降维”；缺 SP 或缺概率就跳过。
- 初盘、现 SP 与【市场漏】用于解释分歧，不覆盖已冻结的球队证据。

### 玩法路由（研究层）

| 情报状态 | 路由 | 说明 |
|---|---|---|
| 方向清 + 净胜清 | 让球 / 比分 | 让球线须与净胜分布一致 |
| 方向清 + 净胜不清 | 胜平负 | 不硬推让球 |
| 方向不清 + 总 λ 稳 | 总进球 | 短期研究常用出口 |
| 方向不清 + 总 λ 不稳 | 观望 | 不给伪精确 |

路由只选价格线，不改 λ、不改矩阵、不放宽出票闸。总进球不自动更安全，须各自算 EV。

### 研究层与出票层

| 层 | 交付 | 闸 |
|---|---|---|
| 【研究玩法】 | 每行带实际 SP、p_model、EV、`标签=非正EV\|正EV` | 不受保守 EV>0 限制；不得进【今日票面】 |
| 【今日票面】 | 实际腿 + `tickets.json` | 数据质量 + 真实 EV + 保守 EV>0 + 预算/开售 |

空仓日仍应交研究玩法（只要该玩法在售且已采 SP）。“无可买/无推荐”必须先证明在售玩法 SP 已采齐并写采集时间。

复式（同场多选）按覆盖算，不按最高赔路径算：

```text
命中概率 = Σp_i
本金 = 2元 × 档数 × 倍数
期望返还 = 2元 × 倍数 × Σ(p_i × SP_i)
EV = Σ(p_i × SP_i) / 档数 - 1
```

加腿只提高覆盖率，不提高 EV。复式 EV 为负仍可作研究玩法，但须标 `非正EV`。

【出票】写 `出票通道=胜平负|让球|进球数|比分|不荐`、`p_be=`、`EV=`、`保守EV=` 和弃因。研究星与投注星分开；不荐时投注星为☆☆☆☆☆。

## 六、比分、总球与汇总

- 方向、概率和主要不确定因素场场可交付；精确比分、总球区间在分布不可靠时明确弃权。
- 【研究推荐】包含方向/倾向；有可靠矩阵才给比分 Top3 和总球分布，不能把“必出三件套”置于证据质量之上。
- 【研究玩法】是研究层交付：写玩法、场次、选项、实际 SP、p_model、EV 和标签；不是投注建议，不进票面。
- 【全场汇总表】保留编号、对阵、排除、推方向、倾向、让球胜平负、比分、进球、强制九列。未估写“未估/弃权”，不硬编数字。
- 强制列只记录赛前有倾向的单选和已实际给出的比分；观望写不定，不进入单选准确率。

## 七、票面与预算

【今日票面】可一张稳、一张博，也可其中一张或全部为空。默认不主动推单关；用户明确允许时才按实际开售和 EV 评估。每腿写玩法、选项、实际 SP、p_model、p_conservative，票面写 `预算=` 与本金。

```text
方案=空仓｜弃因=保守EV不足|数据不足|研究板|预算限制
稳=…｜博=…
账本=过｜EV审计=过｜联合概率=独立近似|保守调整｜一句=审计口径
```

- “稳/博”是波动偏好，不是概率标签。不得用腿排列、主客身份、让平名称或固定返还倍数决定能否进票。
- 不要求每条命中路翻倍，也不为翻倍提高净胜球要求。审计计算实际本金、每条派彩、整票 EV 和保守 EV。
- 多腿联合概率默认可按独立相乘作近似，但必须评估共同联赛、天气、相关叙事和同一信息源造成的相关性；p_conservative 应体现该风险。
- 同场多玩法不能假装独立串关；默认跨场。多张票共用同一腿须合并暴露评估，不按“押客最多一张”机械限制。
- 不败映射成复式会改变本金，必须把全部购买选项列全；不能只算最高赔路径。
- CAUTION/弱置信不是自动禁票或强制复式；由保守 EV 与数据质量决定。票面仍须遵守候选、观望禁票和实际开售。
- 日间可先审计票面；若另写【临场闸】，必须标 `XI=未确认|已确认`。XI 未确认不得写保留，只能撤腿/降观望并重跑受影响概率与 EV。
- 【今晚研究 TOP】【让球稳健推荐】仅作研究导航，每条写 `席=`、`买=`、`盘口=`、`荐=`（无则写无），不另造绕过 EV 的推荐。

## 八、赛前冻结与复盘

`predictions.json` 保存赛前 lean 和完整 P(主/平/客)，或 null；快照禁止覆盖。冻结后发生新信息须新版本，不修改旧文件。

复盘主指标是 Log Loss、Brier 和校准曲线；辅指标为出手率、单选/Top1/Top3、实际 ROI、CLV/最终 SP、最大回撤和置信区间。空仓只记执行状态，方向命中不等于盈利，ROI 不证明概率校准。

每场赛前冻结后追加一行 `pred-ledger.csv`（λ、λ区间、p_model、保守P、实际 SP、closing SP、赛果、模型版本），多腿票另记 `tickets-ledger.csv`（独立近似与保守联合概率、ρ、本金、派彩、命中）。赛后运行 `scripts/score_ledger.py` 出分桶校准、保守P 诊断（Σp_cons 质量、校准缺口、被保守闸挡掉的正EV选项数）、CLV 和 ρ 标定。没有账本就没有校准证据，「概率校准」不得作为宣称。

规则升级采用 walk-forward：固定旧版本 → 用当时可得数据重放 → 在未来样本新旧并行 → 时间外指标改善才替换。禁止拿同一批旧场反复调参后宣称有效，也不用“30场+同类miss3次”自动放行。

## 禁止汇总

- 先算 EV 再编球队故事；把去水概率差当真实 EV；负保守 EV 仍出票。
- 固定 V15.6 概率补丁、固定 RAW 折扣、未验证伤停/战意/天气乘数。
- 用 SP、客热、腿顺序、低结构或“翻倍”硬改方向/票面。
- 强制总进球、强制三比分、强制净胜≥3、按整轮分布改单场预测。
- 旧缺一律无效、新缺一律排边；把荐单/AI 看好方向当事实。
- 同一 λ 在不同玩法使用不同修正；固定 0～5 截断后忽略高比分尾部。
- 用同一旧样本调参与验收；赛后覆盖冻结；把流程绿、空仓或短期 ROI 当准度证明。
- 未采齐在售玩法 SP 就宣布“无可买/无推荐”；把【研究玩法】当投注建议或塞进【今日票面】。
- 用复式覆盖率冒充正 EV；只算复式最高赔路径；用玩法路由绕过保守 EV 出票闸。
