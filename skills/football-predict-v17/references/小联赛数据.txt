═══════════════════════════════════════════════════════════════════════════════
[ANTI_OVERFIT_RULES]
  1) 任何时候都不允许写：
       "IF 某队名/某比分发生了 → λ × N.NN"
       → 只允许：通用二元/连续变量（CB_OUT、GK_OUT、TIER、MinPct…）

  2) EPV_Warning 只能输出文本标记，禁止进入 λ 算术：
       BAD : Lambda_Home *= 1.12   WHEN EPV≠CLEAN
       GOOD: 决策表"⚠EPV"栏写 "CORE_CB_OUT→EPV+"，人工裁决是否抬 λ / 防客偷球

  3) 每个"新系数/变量"上线前必须回答：
       "这条能否对『未来任何同类型比赛』复用？还是只在讲这场故事？"
       → 答不出 = 扔进 Hypothesis_Log，不进 Active_Rules

  4) 禁止词汇（输出层也禁用）："可能"/"或许"/"看好"/"感觉"
       只允许：数值 / 区间 / 标记 / Edge%/NO_ACTION

  5) ★ 新增 V16.2：【数据源诚信铁律】
       - 每个槽位的值必须附 SOURCE_URL 或 SEARCH_Q
       - 当所有来源 FAIL → 写 UNKNOWN → 走 FLAG 分支 → 绝不反向推导假精度
       - 口径不匹配（如 FootyStats的xG ≠ Understat的npxG）→ 必须标注 MODEL=

          SRC_TAG  : "SOFASCORE_MANUAL_ROLL|RAW_GOALS_FALLBACK"
          FLAG     : "⚠ NO_NPXG_HIST → 见 NO_NPXG_HIST 分支"
      }
      IF_ALL_FAIL_HOME: "Home_xG_For_Avg=UNKNOWN  SRC_TAG=NONE  FLAG=[NO_DATA_no_fill]"
