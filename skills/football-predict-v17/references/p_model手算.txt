# p_model 与真实 EV（V18 统一基线）

用途：由可追溯的 λ_H、λ_A 生成同一比分矩阵，再派生胜平负、让球、总进球和精确比分；最后用实际可买 SP 计算 EV。不能从目标方向或目标赔率倒推 λ。

## 1. 输入与不确定度

每场先写：
- 来源、赛事、主客拆分、样本场次、截止时间；xG 与 xGA 同源同口径，是否含点球必须明确。
- 联赛基准、对手强度修正、时间衰减和样本收缩。收缩可用 w=n/(n+k)，但 k 只能来自历史时间外验证；禁止固定 0.65、Edge×0.60 等无验证系数。
- λ_H、λ_A 点估计及区间 `λ区间=H[lo,hi]/A[lo,hi]`，并写 `区间依据=`（样本量、口径、阵容未知中哪个来源撑开）。估计不出就 p_model=null，不填“看起来合理”的数。
- 伤停按球员角色、替补差距和对位估计边际影响；新旧缺不自动对应固定乘数。

可靠矩阵不存在时仍可给定性方向，但不能输出伪精确概率、EV 或可介入票。

## 2. 动态截断独立泊松

P(X=k)=exp(-λ_H)λ_H^k/k!，Y 同理；基线假设 X、Y 独立。

递推：P(0)=exp(-λ)，P(k)=P(k-1)λ/k。

每侧从 0 扩展，过了分布峰值后继续，直到该侧尾部概率 <0.0001；不得固定只算 0～5。程序默认上限 30，达不到精度就报错，不静默归一化。矩阵覆盖率须写出，剩余尾部应可忽略。

P(i-j)=P(X=i)P(Y=j)。所有市场只用这一矩阵。截断后派生概率按矩阵覆盖率归一并披露；精确比分仍同时保留原始概率，不能用归一化掩盖过大漏尾。

可调用 scripts/probability_model.py：score_matrix、result_probabilities、handicap_probabilities、total_goals_probabilities、top_scores。独立泊松是基线；Dixon–Coles、负二项或双变量泊松只有时间外改善 Log Loss/Brier 后才替换。

## 3. 胜平负

P_H=Σ(i>j)P(i-j)，P_D=Σ(i=j)P(i-j)，P_A=Σ(i<j)P(i-j)。

方向不自动等于三项最大者：还需检查不确定度、情报否证和保守概率。主不败/客不败的研究概率可写 P_H+P_D / P_A+P_D；购买复式时每个实际选项仍分别计算 EV 和本金。

## 4. 让球与总进球

竞彩主队让球线 L：主让1为 L=-1，主受让1为 L=+1。调整后净胜 GD'=i+L-j：
- 让胜：GD'>0；让平：GD'=0；让负：GD'<0。

总进球 T=i+j：P(T=n)=Σ(i+j=n)P(i-j)。大小 2.5 分别对应 T≥3 与 T≤2；竞彩多档集合的概率是各档之和。

亚洲两项让球含走盘/半赢半输时不能套竞彩三项公式，须按实际结算规则拆分。不同市场、不同玩法不可把“盘口档数不同”直接解释为机构分歧。

## 5. 市场概率与真实 EV

同一玩法、同一时点、同一结算规则的三项/两项实际 SP：
- 盈亏平衡概率 p_be=1/SP。
- 去水市场概率 q_i=(1/SP_i)/Σ(1/SP)。q 只用于市场基准与校准比较，不是 p_be。
- EV=p_model×SP-1。
- Edge_pp=p_model-p_be，只是 EV 的另一种展示；旧 p_model-p_fair 不再作为出票闸。

反例：SP=1.80，p=51.1%，EV=0.511×1.8-1≈-8.0%；即使 p 略高于去水市场概率，也不值得买。

点估计与保守概率都写。出票要求核心数据足够且保守 EV>0；不再使用胜平负1%、子盘3%、RAW固定折扣等阈值。负 EV 市场直接观望，不要求按顺序“降维”寻找另一个市场。

### 保守概率：λ 区间角点法（禁手填）

保守概率是 λ 不确定度的函数，不是手工下调的常数。做法：

1. 取 λ_H 区间 [h_lo,h_hi] 与 λ_A 区间 [a_lo,a_hi] 的四个角点：(h_lo,a_lo)、(h_lo,a_hi)、(h_hi,a_lo)、(h_hi,a_hi)。
2. 每个角点各跑一次同一动态截断矩阵（第 2 节），派生该玩法概率。
3. 对每个选项取四个角点中的最小值，即 `保守P`。

```bash
python3 scripts/conservative_probability.py --lam-h 1.62 --lam-a 1.05 \
  --h-interval 1.38,1.86 --a-interval 0.86,1.28 --handicap -1
```

输出的 `保守P=` 原样抄进稿件；lint 会重算并比对，手填不一致即 ERROR。

为什么必须这样算：不同玩法对 λ 的敏感方向不同。总进球只依赖 λ_H+λ_A 总量，对主客分配几乎不敏感，最差角点通常是双低或双高；让球依赖净胜，最差角点是单向极端（主胜看 λH低/λA高，客胜看 λH高/λA低）。手工统一打折（如“一律下调5%”）无法区分，结果必然要么总进球过度保守漏掉正 EV，要么让球保守不足买进负 EV，且事后分不清是哪种。

角点法取 worst-case 而非分位数，可能过保守。是否过保守由 `pred-ledger.csv` + `scripts/score_ledger.py` 的保守P 诊断回答（Σp_cons 质量、校准缺口、被挡掉的正EV选项数），不得凭感觉放宽区间。

多腿联合保守概率 = 独立乘积 × ρ。ρ 只能由 `tickets-ledger.csv` 标定；未标定写 `ρ=未标定`，不得把猜测值当估计结果。

宣布“无可买/无推荐”前，须采齐该场全部在售玩法的实际 SP（胜平负/让球/总进球/比分）并写采集时间；未开售写“未开售”。只采了胜平负就说没得买，属于取证不足。

【玩法路由】按情报状态选研究哪条价格线：
- 方向清 + 净胜清 → 让球/比分（让球线须与净胜分布一致）。
- 方向清 + 净胜不清 → 胜平负（不硬推让球）。
- 方向不清 + 总 λ 稳 → 总进球（短期研究常用出口）。
- 方向不清 + 总 λ 不稳 → 观望。
路由只决定研究哪条价格线，不改 λ、不改矩阵、不放宽出票闸。总进球不自动更安全，须各自算 EV。

研究层与出票层分开：【研究玩法】每行带实际 SP、p_model、EV 和 `标签=非正EV|正EV`，不受保守 EV>0 限制，但不得写进【今日票面】；实际出票仍须数据质量 + 真实 EV + 保守 EV>0 + 预算/开售，并进 tickets.json 审计。

## 6. 串关与复式 EV

每条命中路由各腿选项组成。若采用独立近似，路径概率为各腿 p 的乘积；保守概率也必须考虑相关性和共同信息风险。同场多玩法不得当独立串关。

整票本金=2元×路径数×倍数。路径派彩=2元×倍数×该路径 SP 乘积。
整票期望返还=Σ(路径概率×路径派彩)。
整票 EV=整票期望返还/整票本金-1。

复式（同场多选，如“平+客胜”）按覆盖算，不按最高赔路径算：
命中概率=Σp_i；本金=2元×档数×倍数；期望返还=2元×倍数×Σ(p_i×SP_i)；EV=Σ(p_i×SP_i)/档数-1。
加腿只提高覆盖率，不提高 EV。复式 EV 为负仍可作研究玩法，但须标“非正EV”，且不得只列最高赔那一档。

不要求每条路径返还翻倍。所有购买档必须进入 tickets.json，由 audit_delivery.py 核算；p_model 和 p_conservative 是审计必填项。

## 7. 比分与研究输出

精确比分按同一矩阵排序，再用比赛情景检查是否合理；可以只给 Top1/Top3，也可弃权。禁止强制净胜≥3、强制防格、按整轮“小胜太多”改比分。总球分布不可靠时同样可弃权。

V15.6 的 StarFactor/Kryptonite/Jinx/Zombie/Edge_Refine 只保留历史观察标签，不改 λ、P_H/D/A、比分或 EV。任何新修正须先登记特征定义，再经 walk-forward 验证。
