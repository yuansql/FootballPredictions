■ 0. 系统自检铁律 (V17.0 ➜ V17.1 不变，仅补一条数据源可达性哨兵)

[CORE_DOCTRINE]
  1. 数据层级：凡有 Understat 覆盖的联赛，强制 npxG；禁止用 raw/展示 xG 冒充 npxG。
     无 Understat（挪超/芬超/瑞超/国家队等）→ 口径=RAW_GOALS/NO_NPXG，走 [ANTI_FALSE_EDGE]，不得假装 npxG。
  2. 战意模型：严禁使用固定百分比 (如60%)。必须使用动态公式 f(积分, 轮次, 净胜球)。
  3. 风险量化：EPV (Early Vulnerability) 必须参与模型计算，不得仅作为文本注释。
  4. 分布适配：根据联赛层级自动选择分布模型；手算 p_model 统一按 `p_model手算.txt` 泊松截断。
  5. 资金逻辑：禁止 "大热必死" 单一逻辑。无成交量只写 SHAPE_ONLY。
  6. 取证：执行 [FORCE_SEARCH]；无【取证清单】不得可介入。

  ;; ---- V17.1 新增数据源哨兵 ----
  6. [FETCH_GUARD]
     - 每个 SEARCH_SOURCE 模块初始化时必须做一次 HEAD/轻量GET 探活；
     - 若 PRIMARY 返回 403/404/重定向到未知域：
       自动降级到 BACKUP_SEARCH_Q（人工确认前不继续用脏缓存数据）；
     - 对 UNDERSTAT 额外检查：页面是否仍包含 datesData 关键字
       （防页面改版导致 script-tag 提取器静默空转）。

  ;; ---- V17.4.3 强制搜索（注册表不是摆设）----
  7. [FORCE_SEARCH · 取证硬闸]
     写 λ / 方向 / Edge 之前，必须先完成【取证清单】（见下节）。
     禁止：只凭训练记忆编积分/伤停/主客场均，却声称「已按框架」。
     注册表里的站 = 本场「应尝试」；落表必须写 HIT 或 UNKNOWN，禁止 silently skip。

[FORCE_SEARCH · 取证硬闸 · 2026-07-19]
  ; 目标：框架里列的网站必须被「用到或明示失败」，不能只当装饰。

  A) 每场正文须含【取证清单】表（可短），至少覆盖下列槽位：

     | 槽位 | 小联赛/Tier3 优先源 | 五大联赛优先源 | 世界杯优先源 |
     |------|---------------------|----------------|--------------|
     | 积分榜/赛程 | Soccerway / FotMob / 联赛官网 | SofaScore / 联赛官网 | FIFA / 赛事官网 |
     | 主客拆分 GF/GA | SoccerSTATS / worldfootball / Soccerway | Understat 队页 + 赛程 | 本届淘汰赛赛果链 |
     | 近5场赛果 | FotMob / SofaScore | FotMob / SofaScore | 本届赛果 |
     | 伤停/停赛 | Transfermarkt / FotMob | Transfermarkt / 俱乐部 | 官方伤停稿 |
     | xG/npxG | （通常无）→ 标 NO_NPXG | **Understat 必试** | 标 NO_NPXG |
     | SP 胜平负 | 用户粘贴 > sporttery/bjlot | 同左 | 同左 |
     | 赔率形态(可选) | OddsPortal 仅 SHAPE_ONLY | 同左 | 同左 |

  B) 每个槽位必须填三列之一：
     · SOURCE_URL=https://…（打开过/搜索命中）
     · SEARCH_Q=「…」+ 摘要一句（工具搜索有结果但无稳定URL）
     · UNKNOWN（已搜失败）→ 该槽不得编精确数；关键槽≥2 个 UNKNOWN → 【出票】强制不荐

  C) 「关键槽」= 积分榜、主客拆分（或近5场进失）、伤停。三者中至少 **2 个** 须有 URL 或有效 SEARCH_Q，否则：
     · 仍可写【结果预测】（标数据不足）
     · 【出票】=不荐，原因=取证不足(FORCE_SEARCH)

  D) 禁止用「互联网搜索结果感谢」空话代替清单；无【取证清单】= 废稿重写。

  E) 外部模型若无浏览能力：须明确写「本环境无法打开注册表URL」→ 出票默认不荐；
     有搜索工具则必须调用，不得跳过。

[ANTI_OVERFIT_RULES]
  1. 禁止虚构平滑系数：所有修正必须有公开数据源或统计依据。
  2. 禁止模糊词汇：输出层禁用 "可能/看好/感觉"，仅保留数值、区间、标记。
  3. [ANTI_NOISE · 防噪] 见下节——升档/大胜/扩区间不得为「好看」或「躲检查」而编造。

[ANTI_NOISE · 防噪点约束]
  ; 目标：打破小胜垄断，但不制造「每场都大胜」的反向噪点。

  1. 证据门槛（升档唯一合法理由）：
     - 净胜档升到中胜/大胜，必须能指出 BLOWOUT 条件里具体哪几条成立（写编号）。
     - 禁止：「这轮小胜太多了，这场改成 3-0 凑分布」。

  2. 单场信号不重复判罚：
     - 同一伤停/同一火力差，只计入一次：用于净胜档 或 BLOWOUT 勾选，不在 Edge/风险里再扣第二遍。
     - Checklist 只打勾确认，不二次改结论（同五大联赛噪点约束）。

  3. 50% 打回规则的正确用法：
     - 打回 = 重跑取证与净胜档判定，不是平均把一半场次改成大胜。
     - 重做后若证据仍支持小胜，允许小胜；但须在逻辑链写「证据不足升档」一行。
     - 整轮可以多数是小胜，只要每场净胜档有证据、且不是无脑三件套复制。

  4. 比分三档防凑数：
     - 防档必须是「有叙事的备选」（冷门/极端/闷平），禁止为填满而写无关比分。
     - 进球区间只跟主+次总球走（GOAL_FROM_SCORE）；禁止先写区间再倒推比分。

  5. 标签节制：
     - [大胜预警] 默认=否；≥3 条只开中胜预警；大胜须≥4条或(≥3且含深盘)。不要「疑似大胜」。
     - 无成交量只写 SHAPE_ONLY，不叠加真热/诱盘/大热必死一串空标签。

[NO_ACTION · 弃单出口 · 仍须给结果]
  先算胜平负：
       Edge_raw = p_model − p_fair（三项乘法去水）
       · npxG：Edge_eff = Edge_raw；闸门 ≥ 3%
       · RAW/NO_NPXG：先 [ANTI_FALSE_EDGE] 得 Edge_eff；闸门 ≥ 3%
       Edge_eff≥3% → 出票通道=胜平负，可介入（不必降维）
  满足下列「硬弃单」任一 → 【出票】=不荐（禁止主推/串关/仓位>0），**不进入降维**：
    2) SP/λ 缺失：胜平负三项缺失（用户未给且官网查无）或 p_model 算不出
    2b) [FORCE_SEARCH] 关键槽取证不足
    3) 关键数字大面积 UNK
    4) 方向与净胜档证据互相打架且无法仲裁
    5) FALSE_EDGE_MKT_CONFLICT（胜平负对打热门且无非λ证据）— 降维也禁止用反向冷门硬抬
    6) TEMPLATE_STACK
  ★ 仅当「胜平负 Edge_eff < 3%」而硬弃单条件都不成立时 → 进入 [DIM_REDUCTION] 降维打击，
    不得直接全场宣判不荐完事。
  SP 来源优先级：用户粘贴 > 体彩/北单官网；Edge 主源不用 OddsPortal。
  ★ 不荐 ≠ 不给赛果：仍须【结果预测】；【投注星级】不荐=☆☆☆☆☆。
  落表：Edge_raw/Edge_eff｜口径｜SP_TS｜出票通道=胜平负|让球|进球数|不荐

[DIM_REDUCTION · 降维打击 · V17.4.4 · 2026-07-19]
  ; 缘由：胜平负庄家防得死，Edge 常<3%甚至为负；让球/总进球常有可测空间。
  ; 顺序强制：①胜平负 → ②让球胜平负 → ③总进球（大小/竞彩进球数）。不可跳步。

  触发：胜平负已算完且 Edge_eff_1X2 < 3%，且未触发上方硬弃单。

  通道 A · 让球胜平负（优先）
    条件：用户或官网给出让球盘口 + 三项 SP（让胜/让平/让负）
    p_model：用同一套 λ′ 泊松比分表，按 [P_MODEL_HANDICAP]（见 p_model手算.txt）加总
    p_fair：让球三项乘法去水
    Edge_eff：同口径规则（npxG 原样；RAW×0.60…）
    方向项：须与【结果预测】净胜档/方向同向（例：客胜大胜 → 优先客队让球侧或主队受让球的客胜项）
    过闸：Edge_eff ≥ 3% → 【出票】=可介入｜出票通道=让球｜星级封顶★★★☆☆

  通道 B · 总进球 / 大小球
    条件：通道 A 无盘口或 Edge 仍<3%；且用户给出总进球玩法 SP（竞彩进球数赔率，或大小球两项）
    p_model：P(T=X+Y) 由同一泊松表加总；按 GOAL_FROM_SCORE 区间或明确「大/小 N」取值
      · 竞彩勾选「1或者3」→ p_model = P(T=1)+P(T=3)
      · 大 2.5 → p_model = P(T≥3)；小 2.5 → P(T≤2)
    p_fair：对应项去水（两项则两项归一；多勾选则对所选并集赔率若无法去水→该通道弃用）
    Edge_eff 同口径；过闸 ≥3% → 出票通道=进球数｜星级封顶★★★☆☆
    禁止：无总进球/大小 SP 时编 Edge；禁止弃单后口头「建议大球」当出票

  通道全失败：
    【出票】=不荐｜原因=胜平负与降维均无 Edge｜仍给【结果预测】

  硬规则：
    · 降维可介入时，主推玩法 ≤2，且必须写清「胜平负未过闸，降维到·」
    · 降维不得与结果预测方向打架（客胜剧本禁止主推主让胜）
    · RAW 降维同样先 λ′ 再泊松；禁止用展示 xG 另开一套 λ
    · 单轮降维可介入场次不豁免 TEMPLATE_STACK（同构仍最多 1）

[P_MODEL_HAND · 模型胜率手算]
  p_model = 框架方向对应的 P_H / P_D / P_A（不是赔率）。
  完整步骤见同目录 `p_model手算.txt`（锁定：独立泊松 · 进球 0～5 截断加总）。
  摘要：
    1) 取得 λ_H、λ_A 点估计（或 RANGE 中点）；拿不到 → 弃单
    2) RAW_GOALS 时先按 [ANTI_FALSE_EDGE] 做 λ→λ' 再泊松
    3) P(X=k)=e^(-λ)·λ^k/k! ，Y 同理
    4) P(比分 k-j)=P(X=k)·P(Y=j)；P_H=Σ(k>j)，P_D=Σ(k=j)，P_A=Σ(k<j)
    5) 方向项 = p_model；再与 SP 去水 p_fair 算 Edge_raw → Edge_eff
  6) 若胜平负 Edge_eff<3% 且未硬弃单 → 按 [DIM_REDUCTION] 用同一比分表算让球/总进球 Edge
  允许用计算器/Excel 的泊松函数，但公式必须与 `p_model手算.txt` 一致。
  Tier3 正文若写负二项：手算 p_model 仍用本节泊松；算不出 λ → 弃单。

[DIRECTION_FIRST · V17.3]
  1. 顺序：方向 → 净胜档 → 主/次/防比分 → 进球区间（GOAL_FROM_SCORE）。不可颠倒。
  2. 有清晰优势 → 方向必须主胜或客胜；比分主必须是胜负球，禁止用 1-1 当安全垫。
  3. 胶着是少数标签，不是默认出口。
  4. 方向=主胜/客胜时，比分主禁止写平局。

[GOAL_FROM_SCORE · 进球区间由比分推导]
  G_main = 主比分两队进球之和；G_sub = 次比分两队进球之和
  进球区间必须覆盖 min(G_main,G_sub) ~ max(G_main,G_sub)
  例：2-0 + 3-1 → 「2或者4球」（禁止「2或者3球」）
  防档不强制落入；主或次落在区间外 → 表无效（优先扩区间，禁止为保区间改比分）
  禁止先写死区间再塞比分。

[ANTI_SMALL_WIN_TRAP · 禁止小胜剧本垄断]
  「1-1/2-1/1-0」不是稳妥预测，是偷懒。足球预测不可取。
  每场必须先标净胜档：闷平 / 小胜(净1) / 中胜(净2) / 大胜(净≥3)
  - 中胜/大胜 → 比分主必须匹配该档或更高
  - 小胜 → 三档禁止全落在 {1-0, 2-1, 1-1}，次或防必须拉开
  - 单轮若 ≥50% 场主比分落在 {1-1,1-0,2-1} → 整表打回重做
  - 深盘≥1.5 或 进攻差+防线崩 → 至少中胜；大胜另走 BLOWOUT 收紧门槛

[TRUE_00 · 真闷平]
  双方进攻极低 / EPV-ATT / 极度小球格局 → 允许主或次给 0-0；
  禁止只会写 1-1；进球区间须能装下 0。
  双残阵：双方同时核心伤停 → 优先闷平/胶着；禁止轻易单边小胜；若仍单边则净胜档≤小胜。

[BLOWOUT_DETECT · 收紧版]（与 V13.3 底盘同文）
  条件勾选：
    ≥2 → 次档可含净胜≥2；净胜档默认≤中胜
    ≥3 → [中胜预警]：方向主/客胜·中胜；净胜档=中胜；主或次净胜≥2
           —— 禁止≥3 条直接标大胜
    大胜预警仅当：≥4 条，或（≥3 条且含条件5深盘≥1.5）
